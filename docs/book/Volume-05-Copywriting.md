## 1. Tone of Voice Philosophy

### 1.1 The Voice of a Professional Tool

Certilab Platform is a tool for professionals — Arquitectos Técnicos, engineers, and building technicians. The copy must speak to them as a peer, not as a marketing department.

The voice is:

- **Competent:** Speaks with authority. Knows the domain. Uses correct terminology.
- **Clear:** Prefers simple, direct language. Never uses jargon for its own sake.
- **Calm:** No shouting. No exclamation marks. No hype. No urgency.
- **Respectful:** Trusts the user's intelligence. Does not over-explain. Does not patronise.
- **Brief:** Says what needs to be said and stops.

### 1.2 Why Silence Is the Default

The ideal state of the interface is silence. The copy should only appear when it is needed. Every word that can be removed should be removed.

> **Principle:** The best notification is the one you don't have to write.

This applies to:
- Success messages: Confirm the action, then disappear.
- Empty states: Explain the absence, then guide the user.
- Error messages: State the problem and the solution, then move out of the way.
- Confirmations: State what will happen, then wait for the user to confirm or cancel.

### 1.3 The Anti-Corporate Stance

Certilab is not a corporation. It is a professional platform built by and for professionals.

**Avoid:**
- "Innovación disruptiva"
- "Soluciones integrales"
- "Value-added services"
- "Sinergias"
- "Empoderando profesionales"
- "Ecosistema digital"
- "Líderes en el sector"
- "Transformación digital"

**Use instead:**
- Simple descriptions of what the platform does.
- Direct, concrete language.
- Domain-specific terminology where appropriate.
- The first-person plural "nosotros" when Certilab speaks as an entity.

## 2. Tone of Voice Dimensions

### 2.1 Formal vs Informal

| Context | Register | Example |
|---------|----------|---------|
| UI labels and buttons | Neutral | "Enviar solicitud" |
| Error messages | Direct | "No se ha podido guardar" |
| Client-facing emails | Slightly formal | "Estimado/a cliente" |
| AT-facing interface | Professional peer | "Revisa los documentos" |
| Marketing copy | Warm professional | "La segunda opinión técnica que necesitas" |

**Pronoun usage:**
- Always use "tú" (informal/singular) for both AT and client interactions.
- "Usted" may be used in legal documentation and formal contracts only.
- "Vosotros" for addressing groups of ATs in team contexts.

### 2.2 Technical Vocabulary Strategy

**For the AT (professional interface):**
Use the correct technical terms. Do not simplify.

| ✅ Correct | ❌ Incorrect |
|-----------|-------------|
| "Demanda energética" | "Necesidad de energía" |
| "Cerramiento" | "Pared" |
| "Puente térmico" | "Punto frío" |
| "Calificación energética" | "Nota de energía" |
| "Cédula de habitabilidad" | "Permiso de vivir" |

**For the client (public interface):**
Use accessible language, but do not oversimplify to the point of inaccuracy.

| ✅ Correct | ❌ Incorrect |
|-----------|-------------|
| "Certificado energético" | "Papel de la luz" |
| "Eficiencia energética" | "Ahorro de energía" |
| "Segunda opinión técnica" | "Revisión del certificado" |

### 2.3 Consumer-Facing vs Professional-Facing Language

| Aspect | Consumer (Client) | Professional (AT) |
|--------|------------------|-------------------|
| Vocabulary | Simple, explanatory | Technical, precise |
| Sentence length | Shorter | Can be longer |
| Use of examples | Yes, concrete | Minimal, assume knowledge |
| Empathy | Explicit | Implicit |
| Persuasion | Present (marketing) | None (tool) |
| Call to action | Clear, encouraging | Direct, imperative |

## 3. Writing Principles

### 3.1 Clarity Over Cleverness

Every word should be the simplest word that conveys the meaning accurately.

**✅ Correct:**
- "Enviar" — not "¡Lánzate!"
- "Guardar" — not "Preserva tu progreso"
- "No se ha encontrado el expediente" — not "El expediente ha desaparecido en el éter digital"

**❌ Incorrect:**
- Puns, wordplay, or idioms that require cultural knowledge.
- Metaphors that confuse rather than clarify.
- Register that feels like a consumer app.

### 3.2 Precision Over Persuasion

Buttons should describe exactly what they do. Error messages should state exactly what went wrong. Confirmations should state exactly what will happen.

**✅ Correct:**
- Button: "Eliminar expediente" — not "Quitar"
- Error: "El archivo supera el tamaño máximo de 10 MB" — not "Archivo demasiado grande"
- Confirmation: "Se eliminará el expediente y todos sus documentos" — not "Se procederá a la eliminación del expediente"

**❌ Incorrect:**
- Vague button labels that require the user to guess the action.
- Error messages that describe the symptom, not the cause.
- Confirmations that use passive voice to obscure responsibility.

### 3.3 Brevity Without Sacrificing Completeness

Short is better, but only if it communicates everything necessary.

**Three-pass rule:**
1. Write the full text.
2. Remove every word that is not essential.
3. Ensure nothing has been lost in the removal.

**✅ Correct:**
- "El cliente aún no ha subido documentos." (35 characters)
- "Notificar al cliente." (18 characters)
- Total: 53 characters. Complete information + action.

**❌ Incorrect:**
- "En este momento, el cliente en cuestión no ha procedido a la subida de los documentos requeridos para poder iniciar el proceso de revisión." (166 characters)

### 3.4 The Passive Voice Rule

Use active voice. Passive voice obscures who is responsible for the action.

| ✅ Active | ❌ Passive |
|-----------|-----------|
| "El AT ha solicitado correcciones" | "Correcciones han sido solicitadas" |
| "El sistema ha generado el informe" | "El informe ha sido generado" |
| "Has guardado los cambios" | "Los cambios han sido guardados" |

Exception: When the agent is unknown or irrelevant.
- "El pago ha sido procesado." (The system processed it — who is irrelevant.)
- "El expediente se ha cerrado automáticamente." (System action, no specific agent.)

## 6. SEO and Content Strategy

### 6.1 SEO Principles

The public-facing content (landing page, blog, guides) follows SEO best practices for the Spanish market.

- Target keywords: "segunda opinión certificado energético", "revisión certificado eficiencia energética", "arquitecto técnico certificados"
- Content structure: h1 → h2 → h3 hierarchy
- Meta descriptions: 150-160 characters, include primary keyword and value proposition
- URLs: Use Spanish slugs (e.g., `/segunda-opinion-certificado-energetico`)
- Internal linking: Link between related content pieces

### 6.2 Content Strategy Principles

- **Authority over volume:** One well-researched article is worth more than ten shallow posts.
- **Domain expertise:** Content must demonstrate deep knowledge of energy certification in Spain.
- **Practical value:** Every piece of content should help the reader solve a real problem.
- **Professional audience:** Content is written for property professionals, not the general public.
- **Evergreen content:** Prioritise content that remains relevant over time (guides, reference, comparisons).

### 6.3 Content Types

| Type | Purpose | Volume |
|------|---------|--------|
| Guides | How-to content for ATs and clients | 2-3 per quarter |
| Comparisons | Certilab vs alternatives | 1 per quarter |
| Industry analysis | Market trends, regulatory changes | 1 per quarter |
| Case studies | Real examples (anonymised) | 1 per quarter |
| FAQ | Answer common questions | Ongoing updates |

## 7. Accessibility in Copy

### 7.1 Plain Language Principles

- Use short sentences (maximum 20 words).
- Use common words instead of technical jargon for general content.
- Use active voice.
- Write in chronological order for instructions.
- Avoid double negatives.
- Use lists instead of paragraphs for sequential information.

### 7.2 Screen Reader Considerations

- Error messages are associated with inputs via `aria-describedby`.
- Success messages are announced via `aria-live="polite"`.
- Status changes (e.g., "Expediente actualizado") are announced via `aria-live="assertive"`.
- Loading messages use `role="status"` and `aria-live="polite"`.
- Confirmation dialogs use `role="alertdialog"` and `aria-describedby`.
- Icons have `aria-hidden="true"` if decorative, or `aria-label` if functional.

### 7.3 Text Alternatives

- Every image must have alt text that describes its content and function.
- Decorative images use `alt=""` (null alt).
- Functional images (e.g., icon buttons) use `aria-label` or `alt` text.
- Charts and graphs must have a text summary.

### 7.4 Language Tag

All content must use the appropriate language attribute:

```html
<html lang="es">
```

## 8. Copy Checklist

### 8.1 Pre-Review Checklist

Before submitting any copy for review:

- [ ] All text is in Spanish.
- [ ] No untranslated English words remain.
- [ ] Button labels describe the exact action.
- [ ] Error messages state the problem and solution.
- [ ] Empty states include a path forward.
- [ ] Success messages are factual, not celebratory.
- [ ] Confirmation dialogs explain consequences.
- [ ] Placeholder text is an example, not a label.
- [ ] All icons with functional purpose have text alternatives.

### 8.2 Tone Check

- [ ] Would a professional AT find this text respectful?
- [ ] Is there any corporate jargon ("soluciones", "sinergias", "empoderar")?
- [ ] Is there any hype language ("increíble", "revolucionario", "único")?
- [ ] Is there any English where Spanish should be used?
- [ ] Is the text as short as it can be without losing meaning?

### 8.3 Accessibility Check

- [ ] Error messages are linked to their inputs.
- [ ] Status updates are in aria-live regions.
- [ ] Image alt text is present and meaningful.
- [ ] Heading hierarchy is correct (h1 → h2 → h3).
- [ ] Colour is not the only way information is conveyed.

### 8.4 Final Review

- [ ] Spelling checked (Spanish spelling).
- [ ] Grammar checked (concordance, verb tenses).
- [ ] Punctuation rules followed (periods, commas, question marks).
- [ ] Capitalization rules followed (sentence case).
- [ ] Consistent with Volume V editorial guidelines.
