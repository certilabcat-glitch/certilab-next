## Resumen Ejecutivo

Esta release constituye el **cierre oficial del Core V1 de Certilab**, la plataforma SaaS para la gestión de certificados energéticos y segundas opiniones técnicas en Cataluña.

El MVP V1 implementa el flujo completo desde la solicitud del cliente hasta la entrega del resultado por parte del Arquitecto Técnico (AT), incluyendo la gestión de inmuebles, expedientes y documentos.

---

## Objetivo del MVP

Demostrar la viabilidad del modelo de negocio mediante un flujo funcional completo que permita:

1. **Cliente:** Solicitar una segunda opinión técnica sobre su certificado energético
2. **AT (Arquitecto Técnico):** Revisar la solicitud, gestionar el expediente, solicitar correcciones y entregar el resultado
3. **Sistema:** Gestionar el ciclo de vida completo del expediente con trazabilidad y seguridad

### Patrones arquitectónicos
- **DDD** (Domain-Driven Design)
- **Clean Architecture** (separación types / repositories / services / actions)
- **Vertical Slice** (organización por funcionalidad)
- **Single Tenant** con RLS basada en `auth.uid()`
- **Soft Delete** en todas las entidades
- **Optimistic Locking** (versión en cada entidad)

### Bounded Contexts
- **Core Domain:** `src/lib/core/` — lógica de dominio pura
- **Server Actions:** `src/lib/actions/` — orquestación y casos de uso
- **Presentación:** `src/app/` — páginas y componentes
- **Infraestructura:** Supabase (base de datos + storage + auth)

## Flujo Funcional Soportado

```
Cliente
  ├── Registro/Autenticación (auth.supabase)
  ├── Crear solicitud de segunda opinión
  │     └── Datos personales + Datos del inmueble
  └── Mis expedientes
        ├── Ver estado
        ├── Ver documentos
        └── Recibir resultado

AT (Arquitecto Técnico)
  ├── Dashboard (todos los expedientes)
  ├── Revisar expediente (Solicitud)
  │     ├── Aceptar → EnProceso
  │     └── Solicitar correcciones → CorreccionAT
  ├── Gestionar documentos
  ├── Ciclo de correcciones
  │     └── CorreccionAT → CorreccionCliente → Solicitud
  └── Entregar resultado
        └── EnProceso → Aprobado/Rechazado → Entregado

Expediente
  └── Máquina de estados (11 estados, 20 transiciones)
        Solicitud → CorreccionAT → CorreccionCliente → Solicitud
        Solicitud → EnProceso → Aprobado/Rechazado → Entregado
        Solicitud → Rechazado
        EnProceso → CorreccionAT
        Aprobado → Entregado
        Rechazado → Devuelto → PteDocumentacion → Solicitud
        Cualquier estado activo → Cancelado
```

## Limitaciones Conocidas (V2)

| Área | Limitación | Prioridad |
|------|-----------|-----------|
| **PITR Motor** | V1 implementa solo Revisión Manual AT. Motor automático con árbol de decisión es V2. | Media |
| **UX/UI** | Interfaz funcional sin Design System. Sin modo oscuro ni responsive avanzado. | Media |
| **SaaS** | Sin multi-tenant, sin planes de suscripción, sin facturación. | Alta |
| **SEO** | Metadatos básicos. Sin optimización avanzada para buscadores. | Baja |
| **Documentos** | Subida manual por AT. Sin OCR automático ni extracción de datos. | Media |
| **Dashboard AT** | Lista plana de expedientes. Sin filtros avanzados ni búsqueda. | Baja |
| **Notificaciones** | Sin notificaciones push ni email automático. | Media |
| **Auditoría** | Sin log de auditoría completo (solo el implícito por RLS y estados). | Baja |
